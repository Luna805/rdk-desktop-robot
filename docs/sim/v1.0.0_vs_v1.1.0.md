# 模拟对比：v1.0.0 → v1.1.0

> 这是**模拟环境**下的结果，不是真机数据。真机测试流程见 [BENCHMARK.md](../BENCHMARK.md)，结果待补。

## 方法

使用一个本地模拟脚本（未包含在仓库中），从 git 导出两个版本的 `rdk/` 目录，在各自的子进程里导入**未经修改**的 `face_tracker.py` / `ir_wake_bridge.py`，运行它们自己的主循环。只替换硬件边界：

- 时钟（虚拟时间，可快进）
- 摄像头与人脸检测器（按世界模型生成人脸位置，带高斯噪声和 V4L2 帧缓冲）
- 两路 PWM 舵机（连续旋转，每个脉冲转角有随机误差）
- 红外 GPIO（按时间表给出遮挡电平）
- 屏幕串口（支持拔线、换设备名重新枚举、ESP 重启后状态清空）

两个版本使用相同的场景、配置文件和随机种子。

### 模型假设

| 参数 | 取值 | 说明 |
|---|---|---|
| `camera_fps` | 30 | USB 摄像头帧率 |
| `camera_buffer_frames` | 4 | V4L2 缓冲深度；假设 `CAP_PROP_BUFFERSIZE` **不生效**（对 v1.1.0 偏保守） |
| `camera_hfov_deg` | 60 | 水平视场角 |
| `detect_seconds` | 0.035 | 单帧 Haar 检测耗时 |
| `detect_noise_cx` | 0.01 | 检测到的人脸中心抖动（画面宽度比例） |
| `servo_gain_spread` | 0.2 | 每个脉冲实际转角 = 6° × U(0.8, 1.2) |
| 种子数 | 追踪 5 / 触摸 20 | 结果取平均或合计 |

## 结论

| 场景 | v1.0.0 | v1.1.0 | 可信度 |
|---|---|---|---|
| 快速触摸（间隔 0.15–0.5s，60 次序列） | 53/60 次结束后头没回到原位，最多偏离 10 步 | 0/60 | 高：只取决于代码逻辑和点击时序 |
| 运行中拔线重插 | 6.02s 进程退出，屏幕停在重启后的 `idle` | 重插后 0.38s 恢复，补发状态，最终正确进入 `sleep` | 高：只取决于异常处理逻辑 |
| 人脸阶跃（±22°，10 次） | 对准后平均残余偏差 12.5° | 8.4°（降低 32%） | 中：数值依赖视场角等模型参数 |
| 人脸缓慢移动（2°/s） | 7.4° | 7.3°，基本持平 | 中 |

**代价**：阶跃场景中 v1.1.0 的舵机脉冲从 8.4 增加到 14.6 次，对准时间中位数从 0.83s 增加到 1.0s。这是滞回带来的取舍：v1.0.0 偏离进入 0.2 阈值就停，人脸停在画面偏边缘的位置；v1.1.0 继续转到 0.12 以内，所以更准但多转几下。两个版本都没有出现来回抖动（`reversals` = 0）。

**没有体现的**：丢弃旧帧（`flush_stale_frames`）在这组模型参数下没有带来可见差别。

**模拟器额外发现的问题**：最初的 v1.1 修复会在冷却期内直接丢弃点击，在 0.15s 点击间隔下 20 次中有 7 次结束后头停在低位（软件状态正确，但用户最后一次点击被忽略）。已在 v1.1.0 中改为保留最新请求、冷却结束后执行（提交 `50408ef`）。
